# 自动化流程：先规划后执行，成功流程优先复用

## 1. 解决的问题

小爱做界面自动化时，不管是聊天里还是定时任务到点执行，模型只把一句话
传给 `com.xiaomi.voiceassistant.UIAgentServiceForOSBot.controlApp(String)`，
云端按这句话去点。笼统的一句话经常在首页找不到入口——实测：只说
“打开支付宝签到”，云端在首页找不到签到；补成“打开支付宝，点我的，再点签到”
就顺利完成了。问题不是点不了，是模型自己不知道流程。

本功能不内置任何应用、任何任务的流程，只做一个通用机制：**先检索流程，
再按流程执行**，顺序如下。

## 2. 机制：先第一个，再第二个；有成功的优先成功的

开关在模块设置页 → 功能 → 自动化流程 →「先规划后执行，成功流程优先复用」，
默认关闭，与会员解锁开关相互独立。

### 第一步：先规划（没有成功记录时）

新指令是笼统的（少于两步“点击”），hook 在话传给云端之前加一段通用
规划要求：先根据目标应用的实际界面想清楚要依次点哪些按钮、按钮的准确
文字，再依次执行；找不到对应按钮就停下，不要猜测、不要乱点。
已经是分步骤的指令原样放行，不再加前缀。

### 第二步：成功流程优先复用（有成功记录时）

一条分步骤指令成功执行后（返回非错误），hook 把它记下来，键是
“应用（从‘打开XX’取）+ 末步目标（最后一个‘点击XX’的目标）”，
原文存在模块 App 的 `persona` prefs 里（经 `PersonaProvider` 读写，
一行一条，上限 50 条，同应用+目标覆盖旧的）。

下次同样应用、同样末步目标的笼统指令，不再重新规划，直接改写成这条
成功流程。**有成功的，优先成功的**——复用检查在规划之前。

### 记录什么、不记录什么

- 记录：至少两步点击、返回非错误的执行。单步“只打开”不算成功，不记录。
- 不记录：规划前缀的笼统指令——云端实际走了哪几步，本地不知道，不能瞎记。
- 不补全：含支付、转账、付款、下单、购买、充值、提现字样的指令一律原样
  放行，绝不改写。

## 4. 日志（`adb logcat | grep MISoul`）

- `流程注入：先规划后执行`——笼统指令加了规划前缀
- `流程注入：复用成功流程`——用了已记录的成功流程
- `流程注入：记录成功流程 应用 -> 目标`——刚记下一条
- `流程注入：敏感指令原样放行，不补全`——命中支付类红线

## 5. 实测步骤（必须做）

1. 安装本版，在 LSPosed 里启用，作用域只勾超级小爱，强行停止超级小爱再打开。
2. 打开本模块 → 功能 → 自动化流程 → 打开开关（会员解锁开关不用动，除非还要测定时任务）。
3. 前台先测：说一句笼统的自动化需求，看它是否先规划步骤再执行、最终是否完成。
4. 再测一次同样的笼统需求：这次应该走复用，日志里出现“复用成功流程”，
   且不再需要你手动补流程。
5. 再测定时任务：建一个几分钟后的自动化任务，到点看它是否按流程执行；
   前台成功不等于到点成功（锁屏、云端超时都可能影响），到点那次才是真结果。
6. 应用改版导致旧流程失效时，在设置页点“清除已记录的成功流程”，
   再按第 3 步重新走一遍。

## 6. 诚实边界

- 流程只是给云端的文字，不是本地点屏幕的代码；云端超时、锁屏、应用改版
  都可能让一次执行失败，失败不代表 hook 没生效，先看第 4 节的日志定性。
- 记录的成功不等于“永远成功”：按钮改名、挪位置后旧记录会失效，需要清除重记。
- 本功能不解决会员问题（那是会员解锁开关的事），两个开关互不影响。
