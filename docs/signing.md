# 发布签名

## 为什么需要固定签名

早期构建没有发布密钥，走的是临时调试签名。每次构建签名都不同，安卓因此拒绝覆盖安装
（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`），每次升级都得先卸载旧版，模块设置也跟着丢。

现在所有版本都用同一把固定发布密钥签名。只要密钥不丢，往后版本签名一致，可以直接覆盖升级。

## 密钥放在哪

- 密钥文件在仓库之外（本地 `misoul.jks`），**不进代码仓库**
- 构建时由同目录的 `keystore.properties` 指向它，`app/build.gradle` 的 release
  签名配置读这个文件
- 没有 `keystore.properties` 时自动退回调试签名，方便别人克隆后直接编译

## 升级说明

- 直接覆盖安装即可，不用卸载
- 如果某次升级报签名不一致，说明那一次构建没用到固定密钥。先确认 `keystore.properties`
  是否在位、路径是否正确，再决定要不要卸载——不要习惯性地卸载重装
- 卸载会丢模块设置，重装后需在 LSPosed 里重新启用、重新打开各开关

## 密钥丢失怎么办

固定密钥丢了，之后只能换一把新密钥，而换密钥的那一版又得先卸载一次。
所以 `misoul.jks` 与 `keystore.properties` 务必单独备份。
